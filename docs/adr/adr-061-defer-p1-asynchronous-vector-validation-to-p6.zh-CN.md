# ADR-061 — 将 EL2 异步向量的执行验证从 P1 延至 P6

**Translation status:** Current
**Translation source:** [English source](adr-061-defer-p1-asynchronous-vector-validation-to-p6.md)
**Source blob:** `c90f31be8a2ed01ee70064120c980fca85440b96`
**Authority:** 本文是供中文读者使用的译文；[已接受的英文原文](adr-061-defer-p1-asynchronous-vector-validation-to-p6.md)具有权威性。

**日期：** 2026-09-26。
**状态：** 已接受。
**替代：** 无。
**范围：** P1 NC6 意外向量场景的阶段验收与证据归属。本决策不削弱 P1 已安装向量表的契约，不授权 P1 提供 GIC／IRQ 服务，也不规定 P6 的中断实现。
**背景：** 已接受的[架构基线](adr-000-architecture-baseline-v0.1.md)要求 P1 建立最小 EL2 向量表与诊断路径，却将物理 GICv3 和 Host IRQ 生命周期放在 P6（P1、P6 路线图章节及 ADR-032）。当时的 [P1 任务书](../stages/p1/task-book-v0.1.md)又将*实际执行的*意外向量列为 P1-V18 及 P1 退出条件 6 的一部分。P1 屏蔽 DAIF，有意不提供 GIC／IRQ 来源；已记录的 QEMU `virt` monitor `nmi` 探针也没有产生 NMI。[W11 验证](../stages/p1/verification/p1-w11-negative-fault-validation-verification.md)具有成对的 NC1–NC5 证据，但没有真实的 NC6 异步事件。同步指令或直接跳转向量不等价。因此，若不引入 P1 本身排除的机制，P1 无法如实满足当时的阶段门禁。
**决策：** 分开*向量的结构准备*与*真正执行异步投递*。P1 必须保留 16 槽 EL2 向量安装、来源／类别捕获及有界诊断／致命故障契约；P1-V08 仍是静态源码和 Host 覆盖门禁。P1-W11 保留 NC1–NC5 为真实场景：NC1、NC2 继续支持 P1-V02、P1-V06，而修订的 P1-V18 要求 NC3–NC5 的 panic、同步及 MMU 后故障诊断。NC6 既未通过、未豁免，也未改名；其真正执行意外异步 EL2 向量的要求移交给 P6-W12 负责的 P6-V29，以 P6-W02／W03 的 Host GIC 与物理 IRQ 准备为前置条件。P6 必须使用真实且确定性的异步异常来源，至少运行两次，并验证来源／类别、阶段、相关上下文、有界结果及保留的原始证据。同步陷入或直接向量调用永不合格。没有这些证据，P6 不得声称 P6-V29 或阶段完成；若 Host GIC 就绪后 QEMU 仍无法提供适当来源，P6-V29 应保持阻塞，直到批准替代环境或进一步作出架构／验收决策。P6 入口评审须消费 P1 的结构性向量契约，明确记录尚未执行 NC6 的风险，不得把 P1 完成误读为 IRQ 已执行的证明。
**后果：** P1 阶段完成评审可排除 NC6，按修订后的门禁评估，但只能声称异步向量在结构上已准备，不能声称投递已测试。P1-W11 与 P1 证据图须保留历史 NC6 阻塞并链接移交关系；不得追溯改写验证记录，称 NC6 已通过。P6 任务书、P6-W12 计划和移交材料增加此测试与可追溯关系；P6-W03 仍是机制所有者。P1 向 P2／P6 的移交须暴露该开放风险。本 ADR 不授权生产代码、公开 ABI、依赖或新增 `unsafe`。
**备选方案：** 无限期阻塞 P1（如实，但使仅使用 QEMU 且没有 GIC 的阶段无法关闭）；仅为测试在 P1 加入 GIC／IRQ 或取消 DAIF 屏蔽（违反 P1 范围并改变正常安全基线）；将同步故障或直接向量分支算作证据（测试的是另一条路径）；彻底删除意外向量要求（丢失架构安全检查）。选择移交 P6，因为该阶段本就负责首个 Host GIC／IRQ 来源及负面物理 IRQ 评审。
