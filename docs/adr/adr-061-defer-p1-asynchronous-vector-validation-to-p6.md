# ADR-061 — Defer executed EL2 asynchronous-vector validation from P1 to P6

**Date:** 2026-09-26  
**State:** Proposed  
**Supersedes:** None  
**Scope:** Stage acceptance and evidence ownership for the P1 NC6 unexpected-vector scenario. This decision does not weaken P1's installed vector-table contract, authorize P1 GIC/IRQ services, or specify a P6 interrupt implementation.  
**Context:** The accepted [architecture baseline](adr-000-architecture-baseline-v0.1.md) assigns P1 the minimum EL2 vector table and diagnostic path, but places physical GICv3 and the Host IRQ lifecycle in P6 (P1 and P6 roadmap sections; ADR-032). The current [P1 task book](../stages/p1/task-book-v0.1.md) additionally makes an *executed* unexpected-vector case part of P1-V18 and P1 exit condition 6. P1 masks DAIF, intentionally has no GIC/IRQ source, and the recorded QEMU `virt` monitor `nmi` probe did not provide an NMI. [W11 verification](../stages/p1/verification/p1-w11-negative-fault-validation-verification.md) has paired NC1–NC5 evidence but no genuine NC6 asynchronous event. A synchronous instruction or direct vector branch is not equivalent evidence. Consequently P1 cannot honestly satisfy its current stage gate without introducing a mechanism the same stage excludes.  
**Decision:** If accepted, separate *structural vector readiness* from *executed asynchronous delivery*. P1 must retain its 16-slot EL2 vector installation, origin/category capture and bounded diagnostic/fatal contracts; P1-V08 remains a static/source-and-host coverage gate. P1-W11 retains NC1–NC5 as real scenarios: NC1 and NC2 continue to support P1-V02 and P1-V06, while revised P1-V18 requires NC3–NC5's panic, synchronous and post-MMU fault diagnostics. NC6 is not passed, waived, or relabeled: its executed unexpected asynchronous EL2 vector requirement transfers to a new P6 validation ID owned by P6-W12, dependent on P6-W02/W03 Host GIC and physical-IRQ readiness. P6 must use a genuine, deterministic asynchronous exception source, run it at least twice, and verify origin/category, phase, relevant context, bounded outcome and retained raw evidence. A synchronous trap or direct vector call never qualifies. P6 cannot claim that transferred validation ID or stage completion without this evidence; if QEMU remains unable to provide a suitable source after Host GIC readiness, the P6 item remains blocked pending an approved alternate environment or a further architecture/acceptance decision. P6 entry review consumes P1's structural vector contract and explicitly records the unexecuted NC6 risk; it must not misread P1 completion as executed IRQ proof.  
**Consequences:** P1's stage completion review may evaluate its revised gates without NC6 but may claim only structural asynchronous-vector readiness, not tested delivery. P1-W11 and the P1 evidence map must preserve the historical NC6 block and link this transfer; no verification record is retroactively rewritten to say NC6 passed. P6's task book, P6-W12 plan and handoff gain the transferred test and traceability, while P6-W03 remains the mechanism owner. The P1-to-P2/P6 handoff must expose the open risk. No production code, public ABI, dependency or new `unsafe` is authorized by this ADR.  
**Alternatives considered:** Keep P1 blocked indefinitely (truthful but leaves the QEMU-only, no-GIC stage unable to close); add GIC/IRQ or unmask DAIF in P1 solely for the test (violates P1 scope and changes the normal safety baseline); count a synchronous fault or direct vector branch (tests a different path); delete the unexpected-vector requirement entirely (loses an architectural safety check). Transfer to P6 is preferred because that stage already owns the first Host GIC/IRQ source and its negative physical-IRQ review.
