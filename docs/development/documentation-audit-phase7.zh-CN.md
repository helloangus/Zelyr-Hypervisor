## 1. 闭环结论

本轮审计覆盖队列已闭环。审计之后，明确且无歧义的导航及机械文档问题 AUD-007、DOC-MECH-01、DOC-META-01 也已修复并复核。共审阅当前 **981 份 Markdown 文档**：阶段 2 固定快照的 967 份、其后新增的 14 份报告，以及快照后 blob 变化并重新审阅的 20 份文档。[当前树差异台账](documentation-audit-current-tree-delta.csv)记录全部 34 项当前树差异（14 项新增、20 项改动）的完整行范围、blob、章节、权威来源和结论；没有快照文档被删除。

阶段 3 工作包台账仍包含全部 **125 个源计划**。合并生产者输出、消费者输入和边断言后，得到 **217 条不同的有向跨阶段工作包关系**。[跨阶段双向核对台账](documentation-audit-crossstage-bidirectional.csv)在存在时并列两端记录，保留源断言和状态，并明确记录缺少的端点行或状态断言，不以推断补齐。

这是审计闭环，不是契约闭环。已确认的设计契约和责任方事项仍待所属责任方决策并按需处理。审计不批准提案、不选择架构，也不声称 P3–P8 已运行交付。P1 NC6/P6-V29、P2 W04 门槛、P8 machine-value gate 和其他源记录阻塞仍保持各自已声明的证明边界。

## 2. 跨阶段关系清点与结果

清点合并了阶段 3 台账中的三个独立视图：工作包 `outputs`（77 条有向关系）、`upstream_inputs`（123 条）和边断言（100 条含跨阶段工作包 ID 的关系）。合并后为 217 条；源视图互有重叠，不能把行数相加当作唯一关系总数。

| 端点映射中的方向证据 | 关系数 | 审计结论 |
|---|---:|---|
| 同时有生产者输出与消费者输入行 | 17 | 台账并列生产者类型／单位、所有者、生命周期、失败、可用性和验证字段，以及消费者前置条件。准入仍按源状态决定。 |
| 仅生产者输出 | 60 | 记录为单侧声明。生产者承诺本身不能证明消费者准入或消费者验收。 |
| 仅消费者输入 | 106 | 记录为单侧声明。消费者假设本身不能证明生产者交付、可用性或证据。 |
| 仅边断言，端点摘要均无对应行 | 34 | 保留为追溯候选及其来源／状态；不提升为已实现契约。 |
| 缺少带状态的边断言 | 217 条中的 117 条 | 关系出现在端点输出／输入数据中，但没有对应的状态边断言。台账标记为 `not-recorded-in-edge-assertion-ledger`。 |

核对发现 P3-W15 结构化输出摘要有一处审计台账错字：它写为 P4-W15，但源边记录指向 P4-W01，且 P4 清单只定义 W01–W09。现已将 JSONL 与 CSV 工作包台账统一修正为源记录支持的 P4-W01。该修正不改变源设计、工作包数、边断言或状态数，只从关系并集中去掉一条错误端点。

以上数量不表示每条单向关系都是缺陷：单向输入、可选能力、事后反馈或阶段级策略都可能是有意设计。但它们说明，源材料中只有 17 条关系在两个端点摘要映射里都明确列出。现在每条候选关系的缺失侧及其后果都可供责任方处置。阶段 3 已有的依赖环分析区分了真实准入／活性阻塞、有序握手和未来阶段约束。

## 3. 发现与证据边界

本次审计结论如下：

- **覆盖完成：** 当前所有 Markdown 路径均有记录；125 个工作包计划均保留映射；已识别的跨阶段工作包关系都有生产者／消费者并列视图，或明确的缺失侧记录。
- **发现仍未解决：** AUD-001 实现／证据及相关 W08 idle-interlock 缺口、AUD-002–006、AUTH-01、状态／双向追溯缺口和阶段专属阻塞仍待责任方处理。AUD-001 的 W06 设计方向已选择，但不声称已实现或验证。AUD-007（计划／设计导航）、DOC-MECH-01（过期锚点）和 DOC-META-01（当前任务书版本头）随后作为文档维护问题修复，并记录于阶段 6 和综合报告。P3-W15 内部端点错字已作为审计数据维护修正。
- **运行时范围不变：** 阶段 5 的 host tests 和保留工件 custody 检查不能替代新鲜 QEMU、目标构建、硬件、异步 vector、SMP、Guest 或整阶段证据。本次文档核对不需要也没有执行这些测试。
- **责任方决策不属于本次审计代决：** 映射权限／生命周期、P6 完成模式、P7 同步、P8 规范权威／machine values 及任何已接受 ADR 的更改，必须由所属流程决策。完整审计可以记录这些阻塞，但不能代替责任方决定。
