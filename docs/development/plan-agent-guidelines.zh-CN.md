## 权威顺序与范围

规划工作的权威顺序是：

```text
架构 ADR > 当前阶段任务书 > 冻结的 ABI／机型
> 已确立的模块契约 > 阶段内部设计自由度
```

发生冲突时标记 `Architecture Change Request` 或 `ADR Required`；
不得暗自重新设计较高层级的决策。

将每项需求分类为**必需（Required）**、**预留（Reserved）**（不能阻碍未来设计，
但当前不实施）或**范围外（Out of Scope）**。不得提前引入未来阶段功能，
也不得把临时实现变成永久契约。

## 计划的必需内容

每个阶段计划应按适当详细程度提供：

1. 目标、ADR 约束、范围分类、现有依赖和需求到验证的可追溯性。
2. 子系统与模块：职责、不负责事项、输入、输出、拥有的状态、依赖、生命周期及失败边界。
3. 核心对象及所有权：带类型的身份／地址、每项可变状态转换的所有者、生命周期和销毁／撤销语义。
4. 接口与函数契约：前置条件、后置条件、错误、副作用、分配／阻塞／中断上下文规则及 ABI 状态。
5. 明确的生命周期／状态机、初始化顺序、运行时数据／控制流、失败回滚及关闭／资源回收路径。
6. 并发／同步、安全边界、遥测、平台差异、验证计划、退出条件对应关系、扩展点及明确分类的开放问题。

不得以布尔值隐藏状态机、以登记表充当隐含所有者，或以大型 `Manager`／全局对象代替边界。

## 架构约束

- 分开机制与策略。EL2 提供安全的资源机制；管理和调度策略不得泄漏到通用 Core API。
- 保持分层：Core 独立于架构和板卡；Arch 包含 ISA 机制；SoC／Board／BSP／Quirk
  代码留在 Core 外。按平台能力选择行为，不按板卡名称分支。
- 分开 Host 平台与 Guest 虚拟机模型。物理 CPU 与 vCPU 是不同对象；静态绑定是一种调度策略。
- 先建模内存所有权再建立映射。Guest 地址空间、内存对象、区域、DMA 所有权和 IOMMU 状态需要明确且兼容的生命周期。
- 将 Guest、设备、固件和管理域输入视为不可信。除非不变量另有规定，Guest 引起的故障应是可恢复、面向 VM 的错误。
- 授权模型是 Capability／handle + rights + generation。角色、固定 VM ID 及 Control Domain 身份都不等同于授权。
- EL2 不吸收复杂配置解析、认证秘密或通用文件系统。公开的管理／ABI／机型契约须版本化。
- 设备前端／后端职责保持分离；virtio descriptor 与共享内存是安全和一致性边界。设备分配是带回滚的事务。
- 遥测是经过设计的接口，不是不断积累的调试打印。

## 验证与移交

按需规定单元、Host、QEMU、Validation Guest、Linux Guest、安全／属性／fuzz 及真机验证。
说明每项证明什么；QEMU 不定义硬件语义，也不证明真机正确性。

移交前检查架构一致性、范围、明确的所有权和状态权威、失败／恢复、可观测性及每项阶段退出条件。
输出实施级设计和开放问题清单；不能用源码代替计划。
