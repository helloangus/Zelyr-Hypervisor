## 目标

发布供 P3、P4 和 P2 完成评审使用、可评审的 P2 消费者契约、证据索引、已知限制及完成门禁记录。

## 范围

P2-L01–L05：平台发现契约、启动内存所有权规则、P3／P4 移交、
已知限制和阶段门禁证据清单。

## 范围之外

宣布 P2 完成、编写验证证据、解决 P2-ACR-01、设计 P3／P4 内部机制，
或实施任何下游运行时机制。

## 工作顺序

1. 汇集 W01–W09 的规划成果、前置条件、验收编号及已知证据位置。
2. 确立受支持的 P3 契约：CPU 清单、启动 CPU 关系、PSCI／能力信息及分配可用性，不授权 AP。
3. 确立受支持的 P4 契约：Host 拓扑、排除受保护范围、分配／释放及所有权扩展基础，不授权 Stage-2 或 Guest。
4. 记录 PCI、SMMU／IOMMU、GIC 初始化、AP 启动和 Orange Pi 运行时支持的必需限制，以及未解决的 P2-ACR-01。
5. 评审 P2-V01–V13 证据索引、门禁准则、链接、工作包覆盖与无环依赖，不将规划变成完成声明。
6. 向 P3／P4 规划者及后续 P2 验证记录移交契约和完成评审清单。

## 验收与关闭

P2-V12 要求可评审的 P3／P4 消费者契约及证据位置。
P2-V13 要求完整的一包一计划映射、客观验证条件、有效链接、无环依赖及可见的 P2-ACR-01。
只有记录真实评审证据后，两项验证才算满足。

## 移交

P3 和 P4 规划者可消费所述输入和限制。P2 完成评审者在任何 `DONE` 状态前，
必须要求全部 P2-V01–V13 证据，并在获得授权的解决方案前保留 P2-ACR-01。
