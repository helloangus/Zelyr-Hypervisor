## 目标

在任何 P2 消费者解释平台信息前，为启动时提供的 DTB 建立经过验证、可诊断的边界。

## 范围

P2-A01–A04：检查 DTB 是否可用、物理范围及其与镜像是否重叠，验证结构边界，
支持必要的基础 DT 编码，并安全处理未知节点。

## 范围之外

特定平台发现、规范化平台数据、内存分配，以及解析器 crate、API、数据布局或模块结构的选择。

## 工作顺序

1. 确认此工作包可以获得 P1 已记录的启动信息、镜像范围、诊断和 unsafe 边界输入。
2. 定义验证通过后的输入成果，并为缺失、不可访问、重叠、格式错误及不受支持的输入定义明确诊断结果。
3. 确立 P2 所需的 DT 结构与编码覆盖范围，包括经检查的范围，以及可安全忽略和需要诊断的未知节点。
4. 使该边界符合任务书的算术、可移植性和不可信输入约束，不选择具体实施设计。
5. 评审拟采用的 Host 侧证据，使拒绝输入与失控行为能够区分。
6. 为发现、离线检查及后续负向回归消费者记录验证后输入的契约。

## 验收与关闭

P2-V01 和 P2-V02 要求评审／测试证据，证明 DTB 可用性、范围及镜像重叠结果明确，
且格式错误的结构／编码输入得到有界、可诊断的处理。证据属于 `../verification/`；
仅有规划不能满足任一验证项。

## 移交

W02 和 W07 可以依赖经验证的 DTB 输入边界及已说明的诊断结果。
解析器与 API 设计仍未实施。
