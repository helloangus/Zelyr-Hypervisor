## 目标

通过从规范化且实际使用的状态得出的一份检查结果，使 P2 平台与内存信息可观测。

## 范围

P2-H01–H04：平台摘要、规范化启动内存图转储、分配器统计，
以及报告信息与实际使用的平台信息一致。

## 范围之外

检查命令的实现、单独硬编码的报告数据、驱动初始化、外部管理 ABI 或遥测 API 设计。

## 工作顺序

1. 确认 W02–W05 提供检查结果必须呈现的规范化平台、内存图、分配及动态分配信息。
2. 确立架构／EL、启动 CPU／拓扑、RAM／受保护／可分配区域、GIC／定时器／PSCI／控制台及能力的必要摘要内容。
3. 使用与分配和发现消费者相同的权威状态，定义内存图转储与分配器统计结果。
4. 按 ADR 可观测性约束评审此工作包，不选择命令格式、日志 API 或遥测实现。
5. 指定 Host 和 QEMU 验证的检查证据，包括不存在分歧的硬编码视图。
6. 向 QEMU 回归、P3／P4 评审及 W10 移交可观测的 P2 信息。

## 验收与关闭

P2-V08 要求评审／证据表明全部必需检查类别均源自实际使用的规范化状态。
P2-V11 后续提供 QEMU 集成证据；规划此工作包不提供运行时输出或完成证据。

## 移交

W09 和 W10 可依赖所需的检查契约。P3／P4 评审者可用它评估输入就绪情况，
但不得将检查功能视为控制 API。
