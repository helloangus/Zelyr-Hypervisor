## 目标

在开始动态页分配前，建立规范化、经过检查的 Host 物理内存图，标识所有受 P2 保护的范围。

## 范围

P2-D01–D08 和 P2-G01–G03：收集 RAM，保护 Hypervisor／DTB／固件／启动制品，
处理重叠与溢出，规范化内存图，并为后续所有权核算预留扩展路径。

## 范围之外

分配器算法／元数据放置、P4 Guest 内存移交、Stage-2、
`MemoryObject`／`MemoryRegion` 对象设计，以及释放原始 DTB 的任何策略。

## 工作顺序

1. 消费 W02 的规范化 RAM／保留区信息和 P1 权威镜像范围，不假设只有一个 RAM 区或 QEMU 地址布局。
2. 定义可分配、Hypervisor 所有、保留、动态已分配和不可用范围的必需分类。
3. 确立范围检查、重叠、空洞、冲突和零长度处理预期，包括所有权不兼容时明确的致命结果。
4. 按硬性安全门禁和未来 P4 所有权扩展评审受保护范围规则，不设计 P4 对象。
5. 指定用于 Host 和 QEMU 验证的内存图规范化及冲突证据。
6. 向分配、检查、回归和 P4 消费者移交权威的可分配／受保护内存图。

## 验收与关闭

P2-V05 要求证据表明发现的 RAM 和所有受保护范围得到规范化，且冲突处理经过检查、无歧义。
P2-V10 和 P2-V11 后续还要求负向及 QEMU 核算证据。P2-ACR-01 仍未解决，
阻止在此定义 P4 内存对象的任何计划。

## 移交

W04 只能从此内存图推导安全分配范围。P4 获得受保护范围与所有权扩展基础；
此处未实施 Guest 内存机制。
