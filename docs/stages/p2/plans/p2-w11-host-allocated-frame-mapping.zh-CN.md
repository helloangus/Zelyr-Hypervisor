## 目标

为普通分配帧提供明确且受生命周期约束的 Host 访问，使 P3 local areas／栈和
P4 Stage-2 页表／镜像加载缓冲区可以安全初始化和使用。物理分配本身不提供映射访问。

## 范围

必需的 P2-M01–M05：分配帧覆盖与经检查的 HPA/HVA 关系；可写、不可执行的映射属性
和别名约束；所有权与借用生命周期；释放前解除映射／失效和事务性回滚；仅启动 CPU
的验证，以及 `P2-HOST-MAP` 消费者准入。

详细设计需协调 P1 既有启动映射和页表访问、W03 保护及 W04 帧所有权，明确独立
可用的页表存储。W04-MAP 仍负责分配器元数据初始化；W05-MAP 保留堆 backing 与
生命周期适配器，复用 W11 属可选项，需单独审阅集成。

保留：P3 所属 SMP 串行化和跨 CPU 失效的集成，待其契约和证据成立。P2 只提供启动
CPU 操作及后续集成的前置条件。

## 范围外

永久 identity-map／全部 RAM 访问承诺、任意 MMIO 映射、Guest Stage-2／VM 机制、
P2-ACR-01 内存对象、AP 启动、SMP 锁与跨 CPU shootdown、新 Guest／公共 ABI，
以及详细设计前选定映射算法、虚拟地址、Rust API 或模块结构。

## 工作顺序

1. 协调 P1 启动覆盖、W03 保护区、W04 分配与元数据访问及 P3/P4 映射需求，记录缺失输入。
2. 单独审阅帧覆盖、属性、别名、页表存储／启动访问、所有权、生命周期、拒绝、失效和完整回滚的详细设计。
3. 实现并集成已批准的启动 CPU 映射基础和 W04 分配所有权，保留 P1 执行与保护范围。
4. 建立可重复的 host-model 覆盖、边界、生命周期、部分失败、回滚、释放和重用检查，将场景交给 W08。
5. 为栈、页表和镜像缓冲区的代表性用途建立目标／reference-QEMU 分配帧访问及解除映射／重用证据，与 W09 协调配置覆盖。
6. 向 W10 和 P3/P4 记录实际生产者契约、证据及限制；必要设计或证据缺失时保持 `P2-HOST-MAP` 阻塞。

## 验收与闭环

P2-V14 要求明确覆盖、属性和生命周期保证；拒绝受保护／域外与无效生命周期访问；
不存在可写且可执行或冲突内存类型的别名；部分映射失败完整回滚；帧重用前完成解除
映射和失效。host-model 与 reference-QEMU 结果分别记录；栈、页表和镜像缓冲区样本
仅验证 Host 访问，不代表实际 P3/P4 执行。保留 P1 启动连续性。P2-V10/V11 提供更广
回归，P2-V12/V13 审阅消费者契约和规划映射。启动 CPU／QEMU 证据不证明硬件或 SMP
安全；本计划不满足任何验证行。

## 移交

W08 接收映射生命周期／错误场景，W09 接收参考平台集成要求，W10 接收权威生产者
和逐条件证据。P3-W02/W04、P4-W01/W02/W03 仅消费声明的 Host 视图及生命周期／清理
义务。后续 SMP 扩展归 P3。实施记录属于 `../implementation/`，实际结果属于
`../verification/`；编码需要已批准的详细设计。
