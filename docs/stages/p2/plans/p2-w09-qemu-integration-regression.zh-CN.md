## 目标

建立参考平台集成证据，证明 P2 信息、内存核算与诊断在受支持的 QEMU `virt` 配置间保持稳定。

## 范围

P2-K01–K05：标准 AArch64 `virt` 配置、CPU 数量变化、RAM 容量变化、
内存图核算和重复启动稳定性。

## 范围之外

将 QEMU 行为视为架构权威、真实硬件证明、AP 启动、GIC 初始化、Guest 执行，
或新的 QEMU runner。

## 工作顺序

1. 确认 P0 的单一 QEMU runner 入口及 W01–W08 契约／证据可用，不重建 P0 自动化。
2. 定义参考平台所需的配置矩阵，包括 CPU 数量和 RAM 容量变化。
3. 为每种配置确立预期发现结果、受保护内存图核算、分配及 W06 检查观察值。
4. 定义可检测对未初始化状态依赖的重复启动证据，同时将 QEMU 结果与硬件语义证明区分。
5. 对照受保护页硬性安全门禁及 Host 侧负向回归覆盖评审集成证据。
6. 记录所需证据／限制，并向 W10、P3 和 P4 规划者移交参考结果。

## 验收与关闭

P2-V11 要求所述矩阵及重复启动的实际自动化 QEMU 证据，
并要求在其已记录的范围内完成内存图核算，以及实际状态检查的一致性。
P2-V01–V10 仍需分别满足；本计划不声称已执行这些验证。

## 移交

W10 可引用证据位置，并区分已运行／未运行结果。P3／P4 获得参考平台输入基线，
而不是真实硬件证明。
