## 1. 目的与阶段边界

P2 将 P1 提供的稳定 AArch64 EL2 环境，转变为能够从启动信息推导可信 Host 平台事实、
并安全管理 Host 物理内存的系统。可观察的阶段成果是规范化的平台描述、规范化的启动物理内存图、
动态物理页与小对象分配、普通帧的显式 Host 访问，以及这些基础能力的诊断和验证。

P2 不运行 Guest。P3 使用其 CPU 清单、启动 CPU 关系、PSCI 事实、平台能力及分配基础开展 SMP 工作。
P4 使用其 Host RAM 拓扑、保留区排除、页分配及所有权统计基础开展 Stage-2 和 Validation Guest 工作。

### 必需

- 在解释传入的 AArch64 DTB 前验证它，包括活动 DTB 的位置／生命周期及畸形输入诊断；
- 解释 P2 所需的设备树（DT）语义，并安全地容忍可忽略的未知节点；
- 发现 CPU 清单、RAM、保留内存、GICv3 描述、timer、PSCI、`/chosen`／控制台事实及能力摘要；
- 将原始发现结果转换为按能力驱动的统一平台结果，使 Core 无需重新解析 DTB 或按板卡名称分支；
- 构建并规范化启动物理内存图，排除 Hypervisor、活动 DTB、固件／DT 保留区、启动制品、
  分配器元数据及其他已识别保留范围；
- 建立页分配／释放、OOM、多 RAM 区域、对齐、调试检查、统计，以及小对象动态分配基础；
- 使实际规范化结果可检查，提供离线 DTB 检查，并规划 Host／QEMU 负面和集成验证；
- 记录 P3／P4 移交、约束、已知限制及提出 P2 完成声明前所需证据。

### 预留

- 将页所有权扩展到 VM 拥有、共享、DMA 固定、COW、balloon／回收及相关后续阶段状态；
- 后续选择复制并释放原始 DTB、连续分配接口、分配器策略、元数据位置和分配器移交；
- 其他平台能力类型、设备发现及支持等级；
- Orange Pi 3B／RK3566 仅作为离线 DTB 兼容性样本。

### 范围外

- secondary CPU 启动、PSCI `CPU_ON`、SMP 锁、跨 CPU TLB shootdown 或任何 P3 执行机制；
- VM／vCPU 对象、VMID 分配、GuestAddressSpace、Guest 内存映射、Stage-2 转换、
  Guest EL1 入口或 Validation Guest 执行；
- GIC 初始化／IRQ 注入／vGIC、timer 虚拟化、PCI 发现或分配、SMMU／IOMMU、virtio、
  Control Domain、VM 配置、balloon、overcommit、swap／paging、snapshot／COW 或内存热插拔；
- Orange Pi 3B EL2 运行时启动或 Core 中针对板卡的行为。

P2 不得冻结解析器实现、crate／模块树、Rust 类型／API、分配器算法、元数据布局、
锁／并发设计或检查命令布局。这些选择需要后续获批准的详细设计。

## 2. 输入、约束与状态

P0 须提供已记录的 workspace／工具链、日志和 panic 基线、Host 测试与 QEMU runner 入口、
地址／错误约定、unsafe 治理及 ADR／文档流程。P1 须可证明已提供稳定的 QEMU `virt`
AArch64 EL2 Rust 入口、早期控制台及异常诊断、相关 CPU／EL2 寄存器、传入的 DTB 或等效启动信息、
已知的 Hypervisor 镜像物理范围和稳定的 Host 执行环境。缺少 P0／P1 输入是上游缺陷，
P2 不得绕过这些缺陷。

ADR 要求将 AArch64 DTB 发现结果转为 `PlatformInfo`，Core 避免依赖板卡／SoC／QEMU，
消费者按能力而非平台名称查询（ADR-041 至 ADR-045）。ADR 还要求受控 unsafe、
不可信边界上的 checked arithmetic、EL2 动态分配、以所有权为中心的内存演进、诊断及分层验证
（ADR-006、ADR-014、ADR-018、ADR-048、ADR-049）。

阶段完成时，预期的能力链为：

```text
启动 DTB -> 验证输入 -> 规范化平台事实 -> 规范化启动内存图
         -> 安全的可分配页池 -> 动态分配与诊断
```

这是必需成果图，**不**声称该能力链当前已经存在。

## 8. 退出条件与移交

只有 P2-V01 至 P2-V14 均有证据，且满足以下全部条件，P2 才能标为完成：

1. QEMU `virt` 可靠地产生必需平台事实及规范化表示，下游 Core 消费者不通过重新解析 DTB 获取这些信息。
2. 在每个有效的分配／释放序列中，每个受保护物理范围均被排除在分配之外；这是 P2 严格的安全门禁。
3. 页和小对象分配的正常、耗尽及释放行为明确，并具有可观察的统计。
4. 平台摘要、内存图转储和分配器统计反映活动的规范化状态。
5. 存在 Host 侧负面回归与 QEMU 集成证据；离线 QEMU／RK3566 样本检查展示语义可移植性，
   但不声称板卡运行时支持。
6. P3、P4 可以找到移交契约和证据，包括已知限制与 P2-ACR-01。

P3 移交暴露 CPU 清单、启动 CPU 关系、PSCI／能力事实、可用分配能力及 W11 显式 Host 访问契约；不授权 AP 启动。
P4 移交暴露 Host RAM 拓扑、受保护范围排除、分配／释放、所有权统计扩展基础及 W11 Host 访问；
不授权 Stage-2、VM 或 Guest 工作。已知限制至少须明确列出 PCI 发现、SMMU／IOMMU、
GIC 初始化、AP 启动及 Orange Pi 3B 运行时支持属于后续工作。

## 9. 完成评审

提出完成声明前，用以下问题检查验证记录、保持的边界、依赖图与移交：

- 消费者能否区分可信的已发现事实与不支持或不可用的能力提示？
- 是否能证明任何分配路径都排除了全部受保护页？
- 畸形启动输入和范围运算是否按不可信输入处理？
- 是否有 P3／P4 或针对板卡的运行时机制进入 P2？
- P2-ACR-01 是否由授权来源解决，或保留为开放的架构问题？

任一答案不符合要求，都阻止 P2 完成。

## 10. P2-ACR-02 规划修订（2026-10-02）

复用 W11 需要经过审阅的集成，不作为规划依赖，因此不引入分配器／映射初始化环。

扩展后的阶段退出要求 V01–V14 及已交付的 P2-HOST-MAP 证据。P3／P4 交接包括显式
Host 覆盖、属性、生命周期和清理限制；物理分配本身不承诺 Host 访问。P3 负责后续 SMP
同步和跨 CPU 失效。完成审查须检查映射生命周期／回滚证据和两份 ACR 记录。
本修订不规定永久恒等映射、全部 RAM 窗口、新 ABI、Guest 执行或详细 API。

## 11. 责任方授权的最小内存基础

2026-10-02，责任方以“可以”选择 ADR-062 方案 A。P2-W12 拥有最小通用 MemoryObject／MemoryRegion 基础，
P4 拥有 Guest 适配器。本补充记录规划授权，W12 设计入口单独记录详细设计批准；正式 ADR 集成与执行证据仍独立；不改写已接受基线。

| 需求 | 必需成果 |
|---|---|
| P2-N01 | 分配器产生的普通 RAM 后备只有一个所有者；保留实际 W04 句柄，不复制帧权威。 |
| P2-N02 | 稳定对象／视图身份，有界容量、受检查耗尽和旧身份拒绝。 |
| P2-N03 | 有界对象范围视图，校验权限／类型意图；不含架构描述符或 Guest 策略。 |
| P2-N04 | 进行中／存活／撤销中视图保留后备；所属后端证明清理完成前不得释放。 |
| P2-N05 | 构建／映射／清理失败保持所有权或明确保留资源；复用和计数一致。 |
| P2-N06 | 通用基础、Host 适配器、Guest 适配器及后续 SMP 证据分开，不隐含运行准入。 |

| 验证 | 所需证据与通过条件 |
|---|---|
| P2-V15 | Host 测试／审阅覆盖 N01–N06：正常／拒绝生命周期，范围／权限／类型错误，旧身份／容量，部分失败／回滚，清理失败保留，token 遗失，释放／复用与精确分配计数；适配器审阅链接 W11／P4 权威。Host 模型不证明真实映射访问、Guest 执行或 SMP。 |

执行依赖为 W04 所有权 → W12 通用基础 → W11 生命周期集成 → W08／W09／W10。
W12 Host 模型不依赖 W11 硬件；W04-MAP 仍为独立、启动保留的元数据前提，不隐含修改 W05-MAP 或堆所有权。
W08 在 V10 下包含 V15；W09 在 V11／V14 下检查集成 Host 行为；W10 在 V12／V13 下纳入 W12 契约、V15 及 ADR 流程状态。
扩展后的 P2 闭环要求 V01–V15、正式决定集成及全部必需能力证据。

P3 仅取得有证据的启动 CPU 所有权／生命周期事实，并负责 SMP 扩展。
P4-W02／W03／W10 运行准入前须与 W12 协调后备／视图权威；阶段局部句柄名称不等于该关联。
外部后备、共享／捐赠、DMA、COW、热插拔及 Guest 机制仍保留或排除。
存储／API／身份表示是获批设计中的 Implementation Choice；实际转换完成仍由后端负责。
