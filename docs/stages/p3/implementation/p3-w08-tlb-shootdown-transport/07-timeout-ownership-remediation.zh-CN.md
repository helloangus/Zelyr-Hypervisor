## 1. 基线与必需基础

当前生产源码没有 P3 transport。P3-V08 要求目标、完成、并发和超时可诊断，
不要求取消或保证恢复停滞 CPU。修订保持任务书授权范围，P3 唯一操作仍为 TransportNoop。

| 目标 | 已发现缺口 | 必需基础／责任方 | 验收 |
|---|---|---|---|
| 正确消费请求 | 目标读旧 Pending 后可能读到超时复用的新描述符 | W08 保留 Pending 描述符直到目标完成 | DV06 在控制字读取、描述符读取、操作完成处暂停 |
| 拒绝无副作用 | 发布循环在先前写入后仍可能 lookup／notify 失败 | W08 全目标预检；不可能的提交错误终止 | DV04／DV06 混合 ready／busy 时发布状态不变 |
| 安全复用 | 把序号相等当成取消权 | 串行发起下只复用 Empty／Completed | DV01／DV06 延迟目标与序号回绕 |
| 合法同步 | W08 持 SpinLock 等完成，违反 W06 BW-2 | 责任方已选 A：W06 BW-6 准入，收集不持数据锁 | DV05 覆盖竞争拒绝、释放和终止保留；执行待完成 |

必需：不覆盖 Pending、全目标预检、采样超时统计、每 CPU 单一不可重入接收方、显式完成／资源生命周期。
预留：取消、强制重置、hotplug、多请求流水线。范围外：TLBI、VMID／IPA、P3 生产代码。

## 2. 修正后的所有权和超时契约

串行发起方仅在 acquire 观察槽为 Empty 或 Completed 后写描述符，再 release 发布新序号 Pending。
目标 acquire 读 Pending 后读取描述符。仅所属 CPU 消费；消费及绑定操作不可重入。
P6 若引入中断消费，须重新评审协议。

Pending 对发起方不可变，超时后亦然。接收方可能已读控制字或正在执行操作。
超时不是取消、静止、CPU 离线权，也不是释放引用资源的许可。
目标完成全部描述符／资源访问和操作后才 release 发布 Completed；
之后不再访问旧描述符／资源，目标私有诊断只用局部值。

发布前检查全部有效目标；只要任一为 Pending，就返回
`TargetsBusy { busy, excluded }`，不改变描述符、控制字或请求序号。
busy 是预检观察集合，不是原子快照；并发完成可能让重试成功。
不能无限等待或静默移除忙目标。独立目标仍可使用。拒绝不改变新请求发布状态；独立旧请求接收及拒绝计数仍可推进，
因此不保证全局状态被冻结。

在串行发起前提下，预检得到的 Empty／Completed 保持稳定，因为目标只写 Pending→Completed。
保存精确控制字作为发布 CAS 的 expected，不能使用任意 Empty 通配值。
区域引用、编码、目标及通知前提均在写前验证。
发布 CAS 或发布后不可能的 W07 失败须终止并保留槽／资源，不能返回普通无副作用 Err 或局部回滚。

收集把同序号 Completed 观察累计入 acked；达到界限时 unacked 为有效目标减 acked。
迟到完成合法，甚至可能发生在调用方收到 TimedOut 前。结果描述观察，不是取消或同时快照。
下次请求必须 acquire 观察 Completed 才能复用；发起方不得清空 Pending。

已有 u16 序号只是内部相等性标签，不是全局唯一操作 ID 或资源 lease。
回绕安全依赖旧接收方仍可能访问描述符时绝不复用槽，且串行收集期间无其他发起方覆盖当前完成状态。
其他槽可能跨回绕保留旧 Pending；即使序号相同，Pending 仍返回 TargetsBusy。
外部 token 或异步完成等待者须有新的身份／生命周期设计。

## 3. 静态交错审阅和验收

原反例：目标读取 Pending(A)；A 超时；发起方写描述符 B；
目标在序号 A 下读取 B，执行错误操作或完成 CAS 失败。原子描述符本身不能防止此问题。

修订后逐项静态审阅，未执行测试：

- 在读描述符前暂停：预检 Pending，拒绝 B 且不写入；目标恢复后仍读取 A。
- 在执行操作时暂停：同样拒绝，超时不得回收资源；最后一次访问后才发布完成。
- 预检期间完成：保守拒绝或观察 Completed 后复用，均保持请求配对。
- ready／Pending 混合目标：全部预检完成后才发布，拒绝前不写 ready 槽。
- 目标永久停滞：保留占用，独立目标可用，包含它的请求返回忙；不保证恢复。
- 重复唤醒：不可重入的目标消费观察 Completed 或新 Pending，不重复消费旧请求。

DV06 必须针对未来真实实现执行这些调度，并覆盖迟到完成、回绕、停滞超过一个序号周期。
DV03 验证发布与完成可见性，DV05 验证串行化与不可重入。
静态审阅不声称 Host／AArch64 执行。

## 4. W08-SYNC：独立跨包设计冲突

分类：既有模块契约边界的 Architecture Change Request；未提议或选择修改已接受 ADR。

[W06 BW-2](../p3-w06-concurrency-synchronization/04-code-contracts-atomic-and-ordering-policy.md#5-busy-wait-and-waiting-rules-bw)
禁止持锁等待完成，但原 W08 方案要求收集期间持 initiation SpinLock。
BW-4 响应式消费不授予 BW-2 例外；也与 W08“绑定操作始终无锁运行”冲突。
有限收集轮数不证明获取锁、调度或墙钟时间有界。

责任方于 2026-10-02 明确选择 A（“就按A来”）。W06 BW-6 与 W08 已统一为
不持数据锁的单次准入协议，原持 SpinLock 收集方案被取代，BW-2 保持不变。
这解决设计策略选择，不代表最终实现准入或 DV05 已执行。

## 5. 消费者与完成边界

W11 区分忙拒绝、超时观察和最终目标完成，在声明的静止点核对汇总，不在超时时强行相等。
W12／DV06 不得以重置 Pending 清理失败测试；W13 保留相同场景及 blocked／not-run 状态。
W14 R7 须传递超时不是完成或回收权。未来 P4 绑定必须按自身完成／静止契约保留描述符引用对象和转换资源；
P3 的不透明 u64 不提供 lease。P4 当前仅本 pCPU 的基线保持不变。

AUD-002 的危险 Pending 替换条款已移除；整个发现闭环仍需获批且一致的 W06／W08 契约、
实现测试及所属阶段证据。本修订无生产代码、unsafe、依赖或公共 ABI 新增。

## 6. W08-SYNC 决策记录（已选择 A）

责任方已选择方案 A：用立即成功或失败的协议准入状态替代 initiation SpinLock。
这是 W06／W08 边界的显式协调变更，不是给锁改名以绕过 BW-2。
它不授予受保护数据借用，没有等待者自旋争抢，接收方也不获取它。
W06 BW-6 已明确其协议职责和约束，同时保留禁止持 SpinLock／数据锁等待的规则。

已选状态为 Idle → Active(发起 CPU) → Idle。仅一次原子 compare-exchange；
竞争时返回 TransportBusy，不发布、不推进序号。私有不可复制调用 token 标识唯一发起方，
不是外部完成 token；仅持有者释放准入。成功取得准入用 acquire，返回释放用 release，
排序发起方序号／状态访问；槽发布与完成仍使用各自 release／acquire。
新请求不能观察或修改发起方中间状态。

取得准入后先预检所有目标，再发布。TargetsBusy 在无新请求写入时释放准入。
成功或 TimedOut 先把观察结果复制到调用方拥有的数据，再释放准入；后续调用不能改变已返回快照。
TimedOut 保留 Pending 槽和引用资源。发布后不可能的错误保持终止语义，保留槽、资源与准入，
不能清理后把部分发布调用当作可复用。正常返回受检查地释放，不取消或强制重置。

收集有界，期间不持 SpinLock／数据锁 guard；调用方进入时也不得持锁，收集仍服务自身接收义务。
TransportBusy 不保证公平或自动重试。需要重试时由所属责任方提供有界循环，并按 BW-4 服务接收；
禁止隐藏的自旋直到准入成功包装。P3 绑定操作仍是不可重入的 TransportNoop，
后续真实操作须独立评审其有界上下文。发起方停滞可能持续占用准入，应诊断而不是强夺 token。

方案 A 的影响与验收：

- 并发调用从等待串行化改为一个调用准入、其他调用显式忙拒绝；已发布调用仍串行，槽安全性保留。
- 同步修订 W08 错误／伪代码／步骤／DV05、W06 BW 规则、W11 计数、
  W12／W13 竞争测试及 W14 消费者重试语义。
- DV05 在预检／发布／收集暂停发起方，证明竞争方立即无写入拒绝、仍可接收；
  覆盖成功、拒绝、超时后的准入释放。
- 评审部分发布终止、不强夺／重置，以及收集全程无锁 guard。本决策包不是实现证据。

备选 B：保留现有 SpinLock，为 W08 单独规定 W06 BW-2 例外。
还须提供获审阅的有界获取机制（当前通用锁没有）、持锁期间接收／不可重入规则、
锁序分析及修订后的绑定操作上下文。它保留等待式调用，但扩大通用同步策略并增加证明义务，不推荐。

责任方于 2026-10-02 以“就按A来”选择 A，拒绝 B。方向批准授权详细契约及验证计划的协调修订；
生产编码仍需最终设计批准和实际 P3 前置条件。
本决定不批准 W04-MAP、W11、S2-MULTIVM-SCOPE 或其他未决整改事项。
