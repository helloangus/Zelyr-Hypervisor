## 1. 权威和基线

P4 [任务书](../../task-book-v0.1.md)允许单 Validation Guest，证明当前路径一致性；
多 pCPU 与 VMID 演进为预留。P7 [任务书](../../../p7/task-book-v0.1.md)要求多 VM 进展和地址空间隔离，
同时明确禁止在 P7 内修补 Stage-2。没有 Stage-2 运行时实现声明。
本文定义缺失的生产者交付与消费者门禁，不追溯扩大 P4 验收范围。

旧稿 create 仅允许一个存活空间；Active(cpu) 捷径在同一 CPU 上直接返回，不重装寄存器。
A→B→A 后，仅凭这个标志不能确定已安装的 root／VMID。
B 已安装时销毁 A，旧稿当前路径失效／停用也不够安全。W02 修订正文和 W10 详细设计已替换这些捷径；实现和目标验证仍待完成。

## 2. 必需生产者保证

| 义务／责任方 | 必需交接 | 验收 |
|---|---|---|
| P4 Stage-2：空间生命周期 | 存活空间保持独立 root 所有权与 VMID 身份，不暗中复用 VMID | A、B 同一 IPA 映射不同帧；身份耗尽显式失败 |
| P4 激活：已安装上下文 | 每 pCPU 唯一权威已安装空间身份，独立于空间生命周期和 P7 current_vcpu | A→B→A 检查实际 root／VMID 和代次；不得仅凭 Active(cpu) 跳过安装 |
| P4 激活：切换 | 接收期望旧上下文和所选新上下文；硬件改动前验证就绪／所有权；报告确定的结果上下文 | 同／不同 VM 重复切换、idle、错误旧上下文 |
| P4 转换：旧转换 | 跟踪可能保留转换的 CPU，不能只看当前执行者；规定修改可见性、失效完成、VMID 退役 | B 运行时修改非当前 A，再回 A，不使用旧权限／帧 |
| P4 销毁 | 表／backing／VMID 释放前清除执行、安装引用、待选操作与旧转换；不得停用其他空间 | B 当前时销毁 A 不影响 B；静止失败保留资源 |
| P7 生命周期 | 准入后失败必须由明确责任方操作恢复生命周期／current slot，再重新排队 | gate 已置 Running 后、Guest entry 前失败，不出现重复 Running／入队 |

对应 P7 能力准入前，上述为必需。W10 已指定身份、选择、残留完成及非复用 VMID；架构规范评审和运行证据仍是生产者准入义务。
P3 transport 超时不是失效完成；[W08 超时所有权](../../../p3/implementation/p3-w08-tlb-shootdown-transport/07-timeout-ownership-remediation.zh-CN.md)
与 W08 实现／证据仍是独立门禁；责任方已选择 W08-SYNC A，文档契约已协调。

单 pCPU 多 VM 轮转须证明不同上下文和本地旧转换处理，不授予跨 pCPU 移动或同时使用能力。
P7 placement／affinity 还须有生产者驻留 CPU、失效及静止保证。

## 3. 消费者要求的失败契约

生产者必须区分：硬件改动前拒绝；失败后已验证安全的确定上下文；硬件部分改变／状态不确定。
这是语义分类，不冻结 Rust 枚举名称。

只有前两类在生产者清理及 P7 准入撤销完成后，才允许 scheduler retry／idle。
状态不确定须阻止受影响路径继续进入 Guest，保留引用资源，并遵循上位不变量／失败策略；
不能转成普通重新排队或 Guest Faulted。scheduler 标志不能证明硬件已清理。

P7 gate 在激活前已提交 Running 和 current_vcpu；没有 W02 负责的显式撤销，
“失败后仍为 Runnable”就不成立。不能直接重置槽、伪造 Guest exit 或假定入队会完成状态转换。
W02 撤销设计已定义该操作及竞争／统计规则；实现和所有生产者清理证据仍是准入前置。已经完成的退出不能回滚。

## 5. 生产者范围决策记录（已授权）

责任方已授权单独标识的 **P4 所有的 Stage-2 扩展工作包**，专门提供 P7 交接能力（[P4-W10](../../plans/p4-w10-multivm-stage2-handoff.zh-CN.md)），
分别形成任务书补充、有界计划、获批详细设计与验证记录。
保留原 P4 单 Validation Guest 验收与 P5 交接；扩展证据是额外的 P7 前置条件，不能倒填为原 P4 完成证明。

本次已授权编制并协调的范围：

- 必需：多个存活地址空间、独立根表、不复用的不同 VMID、明确容量及耗尽拒绝，
  每 pCPU 的唯一已安装上下文权威、核对旧上下文后选择新上下文，以及安全失败分类。
- 必需：非当前空间修改可见性、可能残留转换的 CPU 跟踪、有界失效完成和保留资源的退役。
  仅本 CPU 的里程碑只能准入单 pCPU 轮换；跨 CPU 的 P7 放置须等待残留转换／静止证据。
- 必需配套：P7-W02 拥有过门禁但未入 Guest 的准入撤销；P7-W04 仅在生产者确认硬件上下文安全后使用。
  调度器不自行写 Stage-2 硬件，也不自创完成权威。
- 保留：VMID 复用／回绕、CPU 热插拔、动态 VM 创建、迁移策略及吞吐优化。
  这些保留项不能删掉已准入 P7 放置所需的跨 CPU 残留跟踪和退役能力。
- 依赖：有证据的基础 P4 内存／Guest 契约、P2 后备内存所有权、P3 同步／传输及其完成／生命周期边界。
  计划授权不允许绕过实现准入条件。
- 验收：相同 IPA／不同后备的 A→B→A；B 保持有效时修改／销毁非当前 A；标识耗尽；
  错误旧上下文拒绝；安全和不确定切换失败；准入撤销无重复 Running／队列成员；
  跨 CPU 旧转换及静止失败时保留资源。Host 模型与 QEMU 执行分别记录。
