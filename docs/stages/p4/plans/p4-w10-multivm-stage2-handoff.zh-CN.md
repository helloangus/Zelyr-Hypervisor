## 目标

交付有证据支持的 Stage-2 生产者契约，让 P7 能在多个存活 VM 地址空间间选择，
并安全退役转换与资源；Stage-2 机制不进入调度器。

## 范围

必需 P4-X01–X06，对应任务书补充中的 P4-V17–V22：独立存活根表、不复用的不同 VMID、
有界容量与显式耗尽拒绝；每 pCPU 唯一已安装上下文权威，与空间生命周期分离；
核验上下文切换和失败结果；非当前空间修改、残留转换 CPU 跟踪、失效完成、静止失败保留资源，
以及面向 P7 的能力／证据交接。

这是基础 W01–W09 契约之后单独验收的扩展，不扩大 P4-V01–V16，也不倒改 P5 单 Guest 交接。
仅本 CPU 里程碑最多准入单 pCPU 轮换；其余生产者证据缺失时不能关闭 W10 或准入 P7 跨 CPU 放置。

必需输入是有证据的基础 P4 契约、P2 分配／映射后备内存及所有权，以及 P3 CPU 身份、同步、通知、
传输完成，包括超时生命周期和 TransportBusy 处理。缺失输入阻塞对应实现／证据，不阻塞编写本计划。
[AUD-004 生产者要求](../implementation/p4-w02-stage2-address-space/06-multivm-handoff-requirements.zh-CN.md)
提供反例与交接义务，并不是获批详细设计。

保留：VMID 复用／回绕、CPU 热插拔、动态 VM 创建、迁移策略、大页／批处理和吞吐优化。
这些保留项不减免已准入 P7 放置所需的残留 CPU 跟踪与退役义务。

## 范围外

P7 运行队列、调度／亲和策略、公平性与生命周期转换权威；P5 公共 ABI／能力；P8 机器定义；
P2／P3 基础实现；不确定硬件状态的自动恢复；在计划中规定新公共 API、模块、寄存器序列或算法。
P7-W02 拥有过门禁但未入 Guest 的准入撤销；W10 提供安全上下文前提，不直接重置调度器状态。

## 工作顺序

1. 将实际 P2／P3、基础 P4 证据与生产者要求核对，列出缺失输入，区分基础完成与本扩展。
2. 形成并审阅上下文权威、身份、修改／残留、完成、退役、失败保留和遥测的详细设计。
   核对 P7-W02／W04 消费者要求，但不把其实现设为循环前置；编码前取得详细设计准入。
3. 实现获批生产者扩展，集成基础 P4 后备内存、表及进出所有权，保留单 Guest 回归路径。
4. 验证 Host 模型的所有权、选择、耗尽、非当前修改／销毁、安全／不确定失败和静止保留，
   单独记录模型限制，不混同目标执行。
5. 建立参考 QEMU 本地及跨 pCPU 上下文／转换证据，覆盖相同 IPA／不同后备的隔离，
   以及完成失败时保留资源；保留可重复输入及原始证据。
6. 为 W09 和 P7-W01／W02／W04／W05／W08／W10／W11 发布生产者能力矩阵、设计／实现记录、
   证据及限制；无支持的消费者能力继续阻塞。

## 验收与闭环

P4-V17–V22 各自需要对应层次的真实证据。只移除创建数量限制不够：A→B→A 必须选择正确根表和 VMID；
修改非当前 A、销毁 A 必须保持当前 B；残留转换范围包括已经不再执行该空间的 CPU。
不能依据超时或调度器标志复用表、后备分配或身份。区分硬件修改前拒绝、已验证安全上下文和不确定上下文；
最后一类保留资源并禁止进入 Guest。

W10 完整闭环需要本地及跨 pCPU 生产者保证。Host 模型不是 QEMU 执行，QEMU 不是硬件证明。
P7 准入撤销及调度工作负载仍是 P7 所有的证据（按适用范围对应 P7-V09／V11／V17／V24），
不能当作 W10 生产者完成。本计划不满足任何执行验收行。

## 交接

W09 单独记录扩展证据，不改写基础 P4／P5 完成。P7-W01 按条件消费能力状态；W02／W04 消费已知安全上下文，
拥有准入撤销；W05 消费独立 VM 选择；W08 仅消费已证明的残留 CPU／静止能力；W10／W11 消费隔离／失败场景。
不得从范围授权或基础单空间契约推导 P7 就绪。

详细设计及实现追踪放在 ../implementation/，真实证据放在 ../verification/。
所属设计解决 Implementation Choice（身份容量、状态表示、串行化）、Specification Investigation
（架构排序／失效）及 Platform Investigation（声明的参考配置）。ADR 冲突继续标为 ADR Required；
本次范围授权不批准修改已接受 ADR。
