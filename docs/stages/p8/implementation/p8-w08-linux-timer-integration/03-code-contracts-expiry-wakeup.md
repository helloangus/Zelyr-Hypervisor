# P8-W08 Code Contracts — Expiry, WFI/Wakeup, and Preemption Continuity

**Status:** Proposed detailed design; implementation and validation are not
claimed.  
**Parent:** [P8-W08 detailed design](README.md).  
**Modules covered:** M3 (expiry engine), M4 (delivery bridge), M5 (WFI/wakeup
bridge). Register contracts are in [02](02-code-contracts-timer-regs.md).

All names are logical contract names (README decision D8); pseudocode is an
implementation outline, not runnable production code. Consumed contracts:
P6-W05 event timer (`docs/stages/p6/plans/p6-w05-el2-generic-timer.md`),
P6-W06 timer state (`.../p6-w06-guest-generic-timer.md`), P6-W07 injection
via [W07 §3](../p8-w07-linux-vgicv3/03-code-contracts-interrupt-flow.md),
P7-W06 block/wakeup (`docs/stages/p7/plans/p7-w06-block-wakeup.md`), P7-W04
transition hooks. Failure boundaries: [01 §6](01-architecture-and-state.md).

## 1. Re-arm contract (M3 core)

```text
Name and stability: guest_timer_rearm(vcpu) -> () — internal
Purpose and caller: derive the vCPU's armed-deadline cache from P6-W06 state
  and the vCPU run state; arm or cancel on the P6-W05 event timer; called by
  M2 handlers, by the vCPU transition-in hook, and after delivery
Inputs: vCPU
Outputs: none; effects are the armed cache + P6-W05 arm/cancel + telemetry
Preconditions: vCPU timer lock held (caller's contract); P6-W06 state present
Postconditions:
  - if (CTL.ENABLE ∧ deadline exists): armed cache = earliest deadline of the
    exposed class, armed on the current pCPU's event timer
  - else: cache cleared, arm cancelled
  - the cache is derived truth only ([01 §3]); any mismatch with P6-W06 state
    resolves in P6's favor at next derivation
State and ownership change: armed-deadline cache (owner: M3 via vCPU); P6-W05
  timer programming via its API
Concurrency/allocation: caller holds the vCPU timer lock; P6-W05 API provides
  its own arbitration; bounded, no allocation
Errors and failure guarantee: an arm failure of the P6-W05 timer is an
  internal fault (W13 path) — the fallback correctness rule is that a missed
  arm must not produce a lost wakeup: on any arm uncertainty, the engine
  marks the deadline "immediate-check at next entry" (fails toward delivery,
  never toward silence)
Security/authorization checks: deadline values are Guest data used only for
  compare/arithmetic
Logic (pseudocode):
  fn guest_timer_rearm(vcpu):
      match P6_W06.enabled_deadline(vcpu):        # None if disabled
          Some(cval) if vcpu.is_being_run() =>
              arm_ok = P6_W05.arm_deadline(current_pcpu, vcpu.id, cval)
              vcpu.timer.armed = if arm_ok { Some(cval) } else { ImmediateCheck }
          Some(cval)                              # not running: no arm
              -> vcpu.timer.armed = None          # [03 §5] continuity
          None => { P6_W05.cancel_deadline(vcpu.id); vcpu.timer.armed = None }
Validation: I4 no-lost-wakeup rows; arm-cancel/arm cycles in DV05
```

## 2. Expiry and delivery contract (M3→M4)

```text
Name and stability: guest_timer_expire(vcpu) -> () — internal
Purpose and caller: the P6-W05 event-timer callback for a vCPU deadline;
  converts expiry into Guest-visible assertion
Inputs: vCPU identified by the timer API
Outputs: delivery via [W07 §3](../p8-w07-linux-vgicv3/03-code-contracts-interrupt-flow.md)
  `vgic_request_irq` with the machine-gated timer-PPI INTID and level config;
  wakeup request via [03 §4](#4-wfiwakeup-contract-m5); telemetry
Preconditions:
  - runs in interrupt/timer context of the pCPU that armed it (bounded work,
    no allocation, no Guest execution)
  - MUST re-validate the assertion condition against live state: the deadline
    may have been reprogrammed, masked, or disabled since arming (the armed
    cache is derived, not authoritative)
Postconditions:
  - assertion condition true: PPI requested (level semantics per README
    decision D5: re-assertion after EOI follows via W07's config carrying
    while the condition holds); if the target vCPU is blocked, a wakeup
    request is issued
  - condition false (stale expiry): no delivery; counter updated; one
    telemetry event
  - if CTL.ENABLE remains set with the same elapsed CVAL (Guest did not
    touch the timer), the level condition persists — no repeated injection
    loop is generated by this layer (level semantics, not edge)
State and ownership change: none owned; P6-W07 pending state via W07 bridge
Concurrency/allocation: bounded interrupt-context work; takes the target
  vCPU's timer lock briefly to re-validate; issues P7 wakeup without joining
Errors and failure guarantee: stale expiry is benign and counted; delivery
  bridge failure escalates via W13; a Guest cannot cause this path to drop
  an assertion silently (fail-toward-delivery rule of §1)
Security/authorization checks: INTID is the machine-gated timer PPI; target
  is the owning vCPU only (I3)
Logic (pseudocode):
  fn guest_timer_expire(vcpu):
      lock(vcpu.timer_lock):
          asserting = P6_W06.ctl(vcpu).ENABLE and !IMASK
                      and P6_W06.cval(vcpu) <= guest_read_vcounter(vcpu.vm)
          if asserting:
              vgic_request_irq(VcpuTarget(vcpu), TIMER_PPI_INTID,
                               Config::LevelAsserted, Source::GuestTimer)
      if asserting and vcpu.is_blocked():
          guest_timer_wakeup_request(vcpu, WakeupSource::TimerExpiry)
      telemetry(expire, asserting)
Validation: P8-V11 timer-IRQ and target-vCPU rows; T5a/T5f scenarios
```

## 3. Deferred-delivery contract (deadline while target absent)

```text
Name and stability: guest_timer_delivery_on_entry(vcpu) -> () — internal
Purpose and caller: vCPU transition-in hook; covers deadlines that passed
  while the vCPU was not running (preempted, blocked-then-woken, or
  stopped-pending-on) — the P6-W06 "eventual delivery when absent" promise,
  made concrete for Linux
Inputs: vCPU at entry
Outputs: delivery if the assertion condition holds; re-arm via §1
Preconditions: called exactly once per Guest entry, before the vCPU runs
  Guest instructions
Postconditions: I4 holds across the absent interval: the deadline is either
  delivered at this entry or was already delivered/obsoleted by Guest
  reprogramming — never silently dropped
State and ownership change: armed cache re-derived; P6-W07 pending via W07
Concurrency/allocation: bounded; vCPU timer lock; no allocation
Errors and failure guarantee: as §1/§2
Security/authorization checks: as §2
Logic (pseudocode):
  fn guest_timer_delivery_on_entry(vcpu):
      if vcpu.timer.armed == ImmediateCheck:      # §1 fail-toward-delivery
          guest_timer_expire(vcpu)                 # re-validates condition
      guest_timer_rearm(vcpu)
Validation: P8-V11 deferred/sleep rows; S5f of [02 §4](02-code-contracts-timer-regs.md)
```

## 4. WFI/wakeup contract (M5)

```text
Name and stability: guest_wfi_block(vcpu) -> () — internal
Purpose and caller: the Guest WFI trap; Linux idle loops issue WFI when no
  work is pending — correctness of sleep/timeout and idle power behavior
  depends on the wakeup rule
Inputs: vCPU issuing WFI
Outputs: P7-W06 block call with the declared wakeup-source set; telemetry
Preconditions:
  - caller is the WFI trap path (vCPU Running, about to block)
  - P7-W06 block/wakeup seam is available ([01 §6](01-architecture-and-state.md)
    boundary)
Postconditions:
  - the vCPU blocks (P7-W06 semantics; no busy-looping — P7's guarantee)
  - wakeup sources, exactly: (a) this vCPU's timer assertion ([03 §2] issues
    the wakeup), (b) any vIRQ made pending for this vCPU (P6-W07 accepted
    request → P7 wakeup via its own seam), (c) Host notification (scheduler/
    management events — P7's source set)
  - a WFI with an already-pending/unmasked wakeup-source present returns
    without blocking (the WFI-as-noop rule for pending events)
  - Guest WFE is classified by W05 and is not a blocking primitive in the
    P8 model (event-stream/SEV semantics out of scope)
State and ownership change: vCPU run state via P7-W06 only
Concurrency/allocation: bounded; no allocation; never holds the vCPU timer
  lock across the block call
Errors and failure guarantee: a failed block call is an internal fault (W13);
  spurious wakeups are permitted and benign (Guest re-evaluates); lost
  wakeups are the failure this contract exists to prevent (I4)
Security/authorization checks: the Guest cannot add or remove wakeup sources;
  WFI is not a privilege boundary
Logic (pseudocode):
  fn guest_wfi_block(vcpu):
      if P6_W07.has_presentable_pending(vcpu) or timer_asserting(vcpu):
          telemetry(wfi_noop); return            # pending event: do not sleep
      P7_W06.block(vcpu, WakeupSources{
          timer:  guest_timer_expiry_for(vcpu),  # armed via §1 if enabled
          virq:   P6_W07.pending_wakeup_for(vcpu),
          host:   P7_default_sources() })
      telemetry(wfi_block)
Validation: P8-V11 WFI rows; sleep/timeout scenario (msleep loop wakes);
  no-busy-loop verified by W17 baseline observations
```

## 5. Preemption and continuity contract (M3 + transition hooks)

```text
Name and stability: guest_timer_on_transition_out(vcpu) -> () — and —
  guest_timer_delivery_on_entry(vcpu) (§3) — internal pair
Purpose and caller: P7-W04 context-switch hooks; together they guarantee I5
  (continuity) and release the pCPU's event-timer resource on every switch
Inputs: vCPU leaving or entering Guest execution
Outputs: out — cancel arm (cache cleared); P6-W06 state untouched (its
  preservation contract is unchanged); entry — §3 + §1 re-arm
Preconditions: hooks invoked by the P7 transition path in its defined order
  (timer hooks after arch context save / before restore, per P7's contract)
Postconditions:
  - the pCPU's event timer never carries a stale arm across a switch to a
    different vCPU (cross-vCPU misdelivery is structurally excluded)
  - Guest-visible time is unaffected by the switch (I1/I5) because the
    counter/offset path has no per-pCPU component
  - repeated switch cycles are state-identical
State and ownership change: armed cache only
Concurrency/allocation: bounded; caller's locking context (P7's switch
  serialization); no allocation
Errors and failure guarantee: a missed cancel is caught by the entry-side
  cancel-then-derive pattern (entry always starts from a cleared cache);
  failures escalate via W13
Security/authorization checks: none beyond P7's context integrity
Logic (pseudocode):
  out:   P6_W05.cancel_deadline(vcpu.id); vcpu.timer.armed = None
  entry: vcpu.timer.armed = None            # defensive clear
         guest_timer_delivery_on_entry(vcpu)   # §3 (includes §1 re-arm)
Validation: P8-V11 preemption rows (deadline across forced preemption);
  W11 consumes this contract for M:N scheduling
```

## 6. Consumer obligations recorded here

- **[W09](../p8-w09-virtual-console-single-cpu-linux/README.md)** may assume
  I1/I2 for boot-time timestamps and timeout loops, and uses §4's rules for
  input-poll sleeps.
- **[W10](../p8-w10-linux-smp-bringup/README.md)** assumes I2/I3 for per-CPU
  timer bring-up and tick correctness across vCPUs, and exercises §4 on every
  idle CPU.
- **[W11](../../plans/p8-w11-scheduler-linux-integration.md)** must preserve
  §5's hook invocation order and I4 under M:N scheduling; any change to hook
  order revisits this design first.
- **[W17](../../plans/p8-w17-linux-performance-baseline.md)** consumes the
  telemetry events (program/expire/deferred/wakeup) with the P6-W13
  measurement method.
- Any consumer needing a second timer class or physical-counter exposure
  extends this design (Reserved triggers, README classification), never a
  local handler.
