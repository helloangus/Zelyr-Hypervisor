## 1. 依据与反例

一次编码可指定多个目标，一次寄存器写可能对应多个接收方确认，因此单位不同。
[Arm DAI0492 v3.0 第 7.2 节、第 36–37 页](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/GICv3_v4_overview.pdf?revision=65f91645-cd52-4795-952b-f01095ff5ef8)
说明 GICv3 中两个发送方重叠发送同 ID SGI，共同目标可能只接收一次；若后一个发送发生在确认之后，则可能再接收一次。
仅仅最终静止，也不能保证尝试次数等于接收次数。这是来源／契约审阅，不是执行证据。

## 2. 必需单位与权威

| 数量 | 单位与权威 | 含义／限制 |
|---|---|---|
| accepted_calls | 完整发出的逻辑调用，W04 发送方 | 不是目标数或确认消息数 |
| register_writes | 实际发出的编码数，W04 发送方 | 不是目标数量 |
| target_attempts[pcpu] | 已发送调用对该目标的信号尝试，W04 | 每次成功调用每个校验成员一次，不是送达次数 |
| validation_rejections | 发出前拒绝的调用，W04 | 零写入／尝试，不是预期丢失补偿 |
| acked[pcpu] | 该 SGI 的接收方确认，W03 | SGI ID 本身不能识别发送方或逻辑调用 |
| completed[pcpu] | W03 完成的中断生命周期 | 不证明消费者延后工作的完成 |

分别记录目标身份／集合与编码数。IRM 要记录候选目标快照，且在精确目标断言前证明实际硬件目标域匹配；
否则该形式的精确证据不可用，不能假定硬件按软件 OnlineSet 自动过滤。

W04 不另建接收权威副本。计数按 W13 有界原子更新约定，防止 IRQ 抢占丢失更新。
快照记录运行／轮次、单位、近似／静止模式及溢出；溢出不能回绕成合法精确差值。
不能通过接收总数差值推算合并或丢失次数。

## 3. 精确比较只属于受控验证场景

DV04／DV05 的逐目标精确断言要求测试框架证明：

1. 独占验证 SGI，初始状态已排空；比较轮次内没有无关发送方／消费者流量。
2. 每个目标／SGI 最多一个未完成尝试；各目标完成 W03 中断生命周期，框架通过测试专用同步观察到本轮完成后，
   才能开始下一轮。这是夹具，不是新增生产 SGI 协议。
3. 目标集合稳定、发送完成、计数无溢出，排空后快照稳定；逐个检查全部目标，并检查未指定的受监控目标没有接收。
4. 观察有界；前提或排空无法建立时明确失败／无法判断。不能减掉失败目标来凑平等式。

此时比较逐目标尝试、确认与 W03 完成差值，不能把寄存器写与它们的总数比较。
一次多目标编码可能只有一次写，却有 N 次独立完成。其他情况下只报告 ObservedOnly／ExactUnavailable；
并发同 ID 测试验证信号行为与记账，不要求每次发送都有一次确认。
不引入 SGI 载荷、重传、公平性或保证完成的承诺。

## 4. 验证与交接

DV02 检查单目标、同亲和多目标及多个编码的单位，拒绝贡献零尝试。
DV05 增加重叠同 ID 发送、并发快照、就绪变化、溢出及受控精确轮次。
Host 假后端不能标成 QEMU／GIC 证据。W11 在 Host 触发／Guest 尾部场景消费这些限制；
W13 将单位和快照前提带入遥测／回归。最终计数模式及存储仍由 W13 拥有。
