## 1. 目的与边界

P0 建立运行时 Hypervisor 开发所需的可重复、受治理的工程基线。完成 P0 意味着 P1
能够开始 AArch64 EL2 最小启动的详细设计，而不用先修复仓库、工具链、构建、质量、文档或诊断基础。

P0 特意**不是** EL2 启动阶段。不要求 EL2 二进制运行、Guest 启动或 QEMU 冒烟测试通过。

### 必需

- 仓库、workspace、工具链、Host 和 AArch64 构建基线；
- 构建／profile、质量、依赖、unsafe、可移植性、诊断、版本、制品及文档治理；
- CI 与 QEMU runner 入口，以及 Host 测试支持；
- 可重复的开发说明、分支／PR 集成政策及 P1 移交材料。

### 预留

- minimal、research、embedded、general、secure、full 等 profile；
- 未来的 Guest、Control Domain、机型、ABI 与遥测制品；
- 未来的 AArch64／QEMU 与 Orange Pi 3B 验证工作。

P0 决策不得使预留项无法实现，但 P0 不实现其运行时机制。

### 范围外

EL2 初始化、异常向量、DTB 解析、分配器与 Stage-2 设计、VM/vCPU、GIC、调度器、hypercall、
capability 实现、设备驱动、virtio、Control Domain、Guest 启动、Linux 和 Orange Pi 3B 启动。
P0 不得冻结这些工作的 crate 边界、模块树、数据布局、API 签名或算法。

## 2. 输入与不可协商的约束

架构基线 ADR 是以下 P0 约束的来源：

- 以 AArch64 和 Rust 为先的 Type-1 Hypervisor；QEMU virt 是参考平台，Orange Pi 3B／RK3566 是首个真实硬件目标。
- 必须有 Cargo workspace 和 no_std Hypervisor 目标；允许必要的汇编及经评审的 unsafe。
- Core 独立于架构、SoC、板卡和 QEMU；平台行为按能力而非板卡名称选择。
- P0 不实现 Guest 机制，但其未来契约要版本化，遥测是一等关注点。
- 不得暗中修改已接受 ADR。冲突须作为 `ADR Required` 问题处理，不属于工作包内部选择。

## 3. 交付层级与阅读顺序

    ADR 基线
      -> P0 任务书（本文：必需成果）
      -> plans/P0-Wxx-*.md（一个有界工作包：范围与工作顺序）
      -> implementation/（实施记录，必要时包括获批准的详细设计）
      -> verification/（证据与完成报告）

`plans/` 提供规划粒度，而不是实施处方。Coding Agent 修改代码前须阅读 ADR、本任务书、
适用的工作包计划、编码指南及已批准的详细设计。若工作包需要模块／对象／接口设计，
应在该阶段的实施／设计记录中创建，不能从任务书条目推断或边编码边发明。

[计划索引](plans/README.md)是特定工作包的权威入口。它提供前置条件和下游消费者，
使 agent 只需加载与该工作包相关的文档。

## 7. 退出条件与移交

只有全部验证 ID 都有证据且以下可观察条件成立，P0 才算完成：

1. 干净环境可按声明的输入，从克隆经工具链、构建、Host 测试到 AArch64 目标构建。
2. Workspace 与质量门禁可支持后续多 crate、多平台工作，而不预先声明最终 crate 边界。
3. 底层代码开始前已有 ADR／文档／阶段治理、unsafe 政策、可移植性约束及诊断语义。
4. `main` 只接受必需在线检查通过的 GitHub PR 所带来的政策后开发变更。
5. P1 有单一 QEMU runner 入口、可识别的构建制品及可发现的移交材料。
6. P0 交付物均不编码未来 EL2、VM、内存、IRQ、设备或 Guest 的实施决策。

P1 移交材料包含本任务书、P0 完成报告、工具链与目标／构建基线、质量／CI 与测试基线、
QEMU runner 基线、诊断／元数据规则、unsafe 与依赖政策、ADR 与文档流程、平台约束、
feature／profile 治理及 P0 依赖图。

## 8. 完成评审

最终评审回答：

- 工程环境是否可重复，并受到适当自动检查保护？
- 下游约束是否清楚，且 P0 没有预先设计下游运行时系统？
- P1 Plan Agent 能否使用所述移交材料开始 AArch64 EL2 最小启动设计？

任一答案为“否”，P0 即未通过。试图在 P0 中决定后续阶段模块／API／运行时设计属于越界，
不能代替完成证据。
